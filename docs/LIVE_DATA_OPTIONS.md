# Live travel pricing and policy data

The application must treat current quotes as dynamic provider responses. It must not invent or reuse a sample price as if it were a quote. If a provider is not configured, the workflow reports the amount or terms as unavailable.

## What can be used at no initial API cost

| Need | Candidate | Free access | What it can provide | Limitation |
| --- | --- | --- | --- | --- |
| Hotel availability and room rates | [Amadeus Self-Service Hotel APIs](https://developers.amadeus.com/self-service/category/hotels) | Free monthly request quota for test and production accounts | Hotel Search can return current room prices and offer/payment details | Requires an Amadeus account and API credentials. Test data is limited/cached and is not a production quote source. Confirm the selected offer's cancellation terms before presenting it as cancellable; production usage above quota is billable. |
| Indian hotel inventory and rates | [MakeMyTrip myPartner](https://mypartner.makemytrip.com/agent/home) | Portal access itself is not a public anonymous API | Dynamic hotel inventory, partner rates, and hotel cancellation policies through the travel-agent portal | The official portal is explicitly for travel agents and signup asks for OTP, PAN, and KYC/business documents. I found no public self-service hotel-search API documentation for this app to integrate. Do not automate/scrape the logged-in website. |
| Tours and guide-like experiences | [Viator Affiliate API](https://partnerresources.viator.com/travel-commerce/affiliate/) | No signup/API access fee for the affiliate program | Product information and availability; selected access levels expose pricing schedules and real-time pricing | Requires partner registration. Basic access does not expose every endpoint or real-time pricing; higher levels require approval/certification. Products are tours/experiences, not a general directory of independent local guides. |
| Hotel search context | OpenStreetMap / current geocoding integration | Public data endpoint, subject to its usage policy | Candidate property/location context | Does not provide dates/occupancy-specific room rates or cancellation terms. |
| Insurance quote | Insurer/broker APIs (e.g. [AXA Partners Travel APIs](https://developers.axapartners.com/travel)) | No generally available anonymous quote endpoint found | A partner integration can quote products and coverage | Requires partner contact and production credentials; coverage and premiums are policy/jurisdiction specific. |

Booking.com Demand API requires a Managed Affiliate Partner account, an API token, and affiliate ID. Expedia Rapid is also a partner integration. They return property-specific rates and cancellation policy data, but they are not anonymous public APIs. See [Booking.com authentication](https://developers.booking.com/demand/docs/development-guide/authentication), [Expedia cancellation policies](https://developers.expediagroup.com/rapid/lodging/shopping/constructing-cancellation-policies), and [Viator partner access levels](https://partnerresources.viator.com/travel-commerce/levels-of-access/).

BookMyShow is for movies, events, plays, sports, and activities; it is not a hotel booking/inventory source ([official site](https://in.bookmyshow.com/)). For the current application, **Amadeus is the practical first API to evaluate** because it documents self-service hotel search and a free request quota. However, its test environment is not a live production quote and a free quota does not mean unrestricted use. It should only be enabled after credentials are configured and a live offer contains the required cancellation policy. If the trip requires a verified free-cancellation deadline and Amadeus does not return one for the offer, the workflow must continue to flag the hotel as unverified. Expedia/Booking.com are alternatives if approved partner access is available. MakeMyTrip myPartner is useful for an eligible travel agent to manually verify/book, but this project cannot lawfully or reliably fetch its portal data without a documented integration agreement/API.

Google Places is not a substitute for a hotel quote API: it offers place data and broad price-level/range fields, not a specific stay's available room rate and cancellation deadline. Its API also requires project billing to be enabled. An LLM can summarize supplied quotes or give clearly labeled planning estimates, but without a live provider it cannot verify changing prices, availability, cancellation penalties, or insurance coverage. The app does not currently call an LLM.

## Current application status

No Amadeus, Viator, hotel-booking, or insurer credentials are configured in this project. Therefore, exact hotel/guide/insurance quotes remain unknown in the live workflow. OpenStreetMap search returns location candidates only and does not verify the hotel category, rooms, current availability, rates, reviews, or cancellation terms. The existing agents preserve this distinction and the Finance Agent does not fill missing prices with constants.

Recommended next integration: Amadeus for date/occupancy-specific hotel offers, followed by Viator for tour products. If verified cancellation deadlines are mandatory, use a partner provider whose response includes explicit cancellation penalties (for example, Expedia Rapid) and validate the policy object for each rate. Add credentials as server-side environment variables and keep them out of React bundles. Insurance requires selecting a provider for the applicable country and eligibility rules; do not infer coverage from an LLM.
